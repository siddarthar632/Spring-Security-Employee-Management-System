# Spring Security Employee Management System

A learning project using Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA, Thymeleaf, and MySQL.

## Features
- Public home page and registration
- Login/logout with Spring Security form login
- BCrypt password hashing
- USER and ADMIN roles
- Authenticated user profile
- ADMIN-only employee CRUD
- MySQL persistence
- CSRF protection left enabled

## Requirements
- JDK 21
- Maven (or the Maven wrapper generated by your IDE)
- MySQL 8+

## Run it
1. Create a MySQL user/database or use a local MySQL account.
2. In `src/main/resources/application.properties`, set the datasource username and password. By default the password uses `DB_PASSWORD`, with `change_me` as a local placeholder.
3. Run `mvn spring-boot:run` from this folder, or import the folder as an existing Maven project in VS Code / Spring Tools Suite.
4. Open `http://localhost:9090`.
5. Register a normal user and test the user-only pages.
6. Demo administrator: `admin@example.com` / `ChangeMe@123`.

The demo administrator is inserted once if it does not already exist. This credential is for local learning only: change it before deployment and never expose a demo password in a real system.

## Access rules
- `/`, `/register`, `/login`: public entry pages (login is managed by Spring Security)
- `/dashboard`, `/user/**`: authenticated users
- `/admin/**`, `/employees/**`: ADMIN role only

## Important notes
- New public registrations always receive `USER`; the form cannot choose an ADMIN role.
- This is a learning baseline, not a production-ready deployment. Before production, use managed secrets, HTTPS, robust error handling, secure admin provisioning, logging/monitoring, and review session/cookie settings.
- `spring.jpa.hibernate.ddl-auto=update` is convenient for local learning. Use database migrations such as Flyway or Liquibase for production.
